Commit AI Resolver is a daily change tracking and regression analysis tool for Microsoft Advertising repositories.
It automatically fetches commits, summarizes them with AI using code diff analysis, and provides a searchable dashboard with an intelligent chat interface.
So you can quickly find what changed and investigate live-site issues without manually reading every PR.

The main dashboard shows a timeline of daily commits across five key repos: Campaign UI, Middle Tier, UI Server, AnB, and Campaign DB.
Each day is summarized with commit counts, risk levels, and change types at a glance.
Clicking a day expands the detail view.
Each commit has an AI-generated summary based on the actual code diff, not just the PR title.
This is important because PR titles are often vague or inaccurate.
Our summaries tell you what the code actually changed.

Let's walk through a real scenario.
A manual tester has filed a bug.
Let me paste the ADO work item link directly into the chat.
The system reads the bug description automatically, including any attached screenshots.
This is multimodal support.
It can parse the text description, repro steps, and even analyze images the tester attached to understand what went wrong visually.
You don't need to manually summarize the bug, just drop the link.

Based on the bug details, it identifies the relevant feature area and time window, then searches through AI-generated commit summaries to find suspect commits.
Traditionally, you'd read the bug, mentally map it to a code area, then scroll through dozens of PRs reading vague titles like "code cleanup" or "fix issue."
That can take 30 minutes or more.

It returns a list of suspicious commits ranked by relevance, showing who authored them, what code actually changed, and why they might be related to this bug.

Now I ask it to investigate further.
It digs deeper into each suspect commit, analyzing the specific code changes, explaining how they could have caused the reported behavior, and confirming which commit is the most likely culprit with a clear explanation of the causal chain.

This is the key value: from a bug link to a confirmed suspect commit in under a minute, with full reasoning you can share directly with the dev who owns the fix.

Beyond the web dashboard, Commit AI Resolver is available as an MCP server and as a GitHub Copilot CLI / Claude Code skill.
This means any DRI agent or AI workflow can query commit data programmatically, and this matters a lot for real workflows.

Here I'm asking: what recent changes are related to asset performance prediction score?
This is a feature that spans multiple repos and multiple authors.
In a traditional workflow, you'd have to know which repos to check, search through each one's PR history, and read through dozens of diffs.
With the MCP tool, one natural language query returns everything relevant across all tracked repos.

Why does this matter as an MCP integration?
Think about the DRI routine.
When you're on-call and an alert fires, say prediction scores are suddenly inaccurate, the first question is always "what changed recently?"
Today, the DRI manually checks deployment logs, opens ADO, browses PRs, and reads diffs.
That's 20 to 30 minutes before you even start debugging.

With MCP, a DRI triage agent can do this automatically.
It receives the alert, calls our search commits tool to find recent changes in the prediction score area, cross-references with deployment timelines, and presents the DRI with a shortlist of suspect commits.
All before the human finishes reading the ICM ticket.

It's not just DRI either.
A release validation agent can query what config flags changed today before signing off a deployment.
A code review agent can pull related recent changes to give reviewers broader context.
Any agent that needs to answer "what changed?" can plug in Commit AI Resolver as an MCP tool.
No custom integration needed, just connect and query.
