Commit AI Resolver — 5-Minute Demo Script
==========================================

[0:00–0:20] Opening
--------------------
"Commit AI Resolver is a daily change tracking and regression analysis tool
for Microsoft Advertising repositories. It automatically fetches commits,
summarizes them with AI using code diff analysis, and provides a searchable
dashboard with an intelligent chat interface — so you can quickly find what
changed and investigate live-site issues without manually reading every PR."


[0:20–0:50] Dashboard Overview
-------------------------------
(Show the Timeline view)

"The main dashboard shows a timeline of daily commits across five key repos:
Campaign UI, Middle Tier, UI Server, AnB, and Campaign DB. Each day is
summarized with commit counts, risk levels, and change types at a glance."

(Click into a specific day)

"Clicking a day expands the detail view — each commit has an AI-generated
summary based on the actual code diff, not just the PR title. This is
important because PR titles are often vague or inaccurate — our summaries
tell you what the code actually changed."


[0:50–1:50] Scenario 1: Bug Investigation — Finding Suspect Commits
---------------------------------------------------------------------
(Open the chat panel)

"Let's walk through a real scenario. A manual tester has filed a bug —
let me paste the ADO work item link directly into the chat."

(Paste: https://msasg.visualstudio.com/Bing_Ads/_workitems/edit/10552393)

"The system reads the bug description automatically — including any
attached screenshots. This is multimodal support: it can parse the text
description, repro steps, and even analyze images the tester attached to
understand what went wrong visually. You don't need to manually summarize
the bug — just drop the link."

(Show the AI reading the bug and identifying the affected area)

"Based on the bug details, it identifies the relevant feature area and
time window, then searches through AI-generated commit summaries to find
suspect commits. Traditionally, you'd read the bug, mentally map it to a
code area, then scroll through dozens of PRs reading vague titles like
'code cleanup' or 'fix issue.' That can take 30 minutes or more."

(Show the streaming response with suspect commits listed)

"It returns a list of suspicious commits ranked by relevance — showing
who authored them, what code actually changed, and why they might be
related to this bug."

(Type follow-up: "Investigate these commits")

"Now I ask it to investigate further. It digs deeper into each suspect
commit — analyzing the specific code changes, explaining how they could
have caused the reported behavior, and confirming which commit is the
most likely culprit with a clear explanation of the causal chain."

(Show the detailed investigation response)

"This is the key value: from a bug link to a confirmed suspect commit
in under a minute — with full reasoning you can share directly with the
dev who owns the fix."


[1:50–2:50] Scenario 2: Finding Changes by Person and Feature Area
--------------------------------------------------------------------
(Type query: "Can you find the UI changes from Yi Zhang where he added
logs for ad editor view?")

"Here's another common scenario. You want to find what a specific person
changed in a specific feature area. Normally, you'd search through PRs by
author, read each PR title — but titles are often vague like 'update files'
or 'fix issue.' You'd have to open the actual PR diff to confirm what
changed. That's time-consuming when someone has dozens of commits."

(Show the streaming response with relevant commits)

"With Commit AI Resolver, you just describe what you're looking for in
plain language. The system searches through AI summaries generated from
the actual code diffs — so even if the PR title said 'minor update,' our
summary captures that logging was added to the ad editor view. You get
accurate results regardless of how well the PR was titled."

(Type follow-up: "What about similar changes from GitHub Copilot?")

"Follow-up questions work with conversation context. Here I'm asking
about the same type of change — logging in ad editor — but from a
different author. This is useful when multiple people work on the same
feature area and you want to see the full picture of what was modified,
by whom, without manually cross-referencing PRs."

(Show the response)

"Notice how it finds relevant commits even though the query is
conversational. It understands 'similar changes' means the same feature
area — ad editor logging — and filters to a different author. You'd never
get this from a simple PR title search."


[3:40–4:30] MCP & Skill Integration for DRI Agents
-----------------------------------------------------
(Switch to a terminal / GitHub Copilot CLI session)

"Beyond the web dashboard, Commit AI Resolver is available as an MCP server
and as a Copilot CLI / Claude Code skill. This means any DRI agent or AI
workflow can query commit data programmatically — and this matters a lot
for real workflows."

(Type in Copilot CLI: "What recent changes are related to asset
performance prediction score?")

(Show the skill/MCP returning relevant commits)

"Here I'm asking about recent changes to asset performance prediction
score — a feature that spans multiple repos and multiple authors. In a
traditional workflow, you'd have to know which repos to check, search
through each one's PR history, and read through dozens of diffs. With
the MCP tool, one natural language query returns everything relevant
across all tracked repos."

"Why does this matter as an MCP integration? Think about the DRI routine.
When you're on-call and an alert fires — say, prediction scores are
suddenly inaccurate — the first question is always 'what changed recently?'
Today, the DRI manually checks deployment logs, opens ADO, browses PRs,
and reads diffs. That's 20-30 minutes before you even start debugging."

"With MCP, a DRI triage agent can do this automatically. It receives the
alert, calls our search_commits tool to find recent changes in the
prediction score area, cross-references with deployment timelines, and
presents the DRI with a shortlist of suspect commits — all before the
human finishes reading the ICM ticket."

(Show the MCP tool call and response in the agent flow)

"It's not just DRI either. A release validation agent can query what
config flags changed today before signing off a deployment. A code review
agent can pull related recent changes to give reviewers broader context.
Any agent that needs to answer 'what changed?' can plug in Commit AI
Resolver as an MCP tool — no custom integration needed, just connect
and query."


[4:30–5:00] Closing
---------------------
"To recap: Commit AI Resolver solves the problem of understanding what
actually changed across your codebase. It goes beyond PR titles by
analyzing real code diffs with AI. Testers can trace bugs to suspect
commits in seconds. Developers can review changes by person or feature
area without reading every PR. And with MCP and skill integration, DRI
agents can query commit intelligence programmatically as part of their
incident triage workflow. Thank you."


===========================================
Recording Tips
===========================================
- Start the UI dev server (npm run dev in ui/) and API server
  (node api/server.js) before recording
- Use a dark theme for better screen recording contrast
- Have pre-planned queries ready so there's no awkward typing pauses
- The SSE streaming effect looks great on video — let it play out naturally
- For the MCP/skill demo, have a GitHub Copilot CLI session ready with the
  commit-resolver skill loaded
- Consider using a real recent bug example to make the demo more compelling
